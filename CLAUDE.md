# CLAUDE.md

## What this is
Single-file interactive trip planner for a 10-night family (3 people, one 11-year-old) Ring Road + Snæfellsnes loop of Iceland, Sep 19–29 2026. Two selectable itineraries — Plan A (classic coast) and Plan B (highland edition) — behind tabs. Everything ships in `index.html` plus a thin PWA shell: no build step, no dependencies, works from disk (`file://`) and installs offline over http(s).

## Architecture
- `index.html` — all markup, CSS, vanilla JS inline.
- **`PLANS` registry is the single source of truth.** `PLANS.classic` and `PLANS.highland` each carry: `label`, `desc`, `days[]`, `upgrades[]` (chip label + day number), `bookings[]` (label + meta), `stats` (km/stops/soaks/flex; `stops` is computed by reduce, `flex` is raw HTML injected with innerHTML).
- **Shared day objects (`DAY1`, `D5TO10`) are reused across plans by reference — edit them once.** Days **1, 6, 8, 9, 10** are the *same objects* in both plans (as are `STAY2`/`STAY3`/`STAY5`/`STAY7` — nights 5 and 7 base on Egilsstaðir and Akureyri in both plans, so one stay object hangs off both day-5 and both day-7 literals; `STAY4` is Plan A only); days 2, 3, 4, 5, 7 are plan-specific literals. Note `D5TO10` is a misnomer: it holds days 6, 8, 9, 10. **Nothing may mutate a day object** — no in-place `.sort()`, no normalizing, no memoizing onto `d` — or it corrupts the other plan. `dayLight()` is deliberately a pure reader — it takes the previous day as an argument rather than looking it up and caching.
- **Day shape:** `{n, dow, date, km, depart, arrive, title, base, baseLL:[lat,lon], stay?|hotels[], note?, stops[]}`. A `stay` object (`{name, addr, ll, q, status}`) marks a confirmed booking and renders the green Booked card (`q: null` falls back to lat/lon map links); `hotels[]` renders budget-pick chips linking to Google Maps searches. `note` renders as the amber day-level callout (weather gates, alternatives).
- **Stop shape:** `{name, ll:[lat,lon], time, drive?, tag?, note}`. `tag` ∈ `booked | book | soak | opt`. `booked` and `book` are the same thing at different stages — both are timed reservations and both render amber on the map; the card chip distinguishes them (green "Booked" vs amber "Book now"). Flip a stop to `booked` when its confirmation lands, and put the reference in the note. `drive` renders the dashed connector ("drive 45 min") before the stop. Every stop gets Google (`gLL`) and Apple (`aLL`) map links.
- **Map:** static layer built once (`buildMapStatic`: hand-simplified `COAST` polygon, glacier ellipses, KEF pulse) + dynamic layer per plan (`buildMapDynamic`: routes + stop/base markers inside `#dyn`, replaced on plan switch). Equirectangular projection with cos(65°) correction (`px()`); `smoothPath()` is Catmull-Rom → cubic bezier. Stylized — not navigation-grade.
- **Map colors must stay `var(--d{n})`, never resolved hex** (`dayVar()`), so the map flips theme live without a rebuild. They must be assigned via `.style.stroke`/`.style.fill`, **never as SVG presentation attributes** — `stroke="var(--d3)"` is invalid as an attribute and silently falls back to initial (invisible routes, black markers).
- **Sync:** `switchPlan(key, userAction)` re-renders dyn map, rail, cards, upgrades, bookings, hero stats (`#st-km/#st-stops/#st-soak/#st-flex`) and plan description, then resets to "all days"; `selectDay(n)` syncs rail pills ↔ map dimming ↔ auto-opened `<details>` cards. `buildRail()` reads the **active** plan and must be re-run on switch.
- **Persistence** (`localStorage`, all reads/writes try/catch'd so `file://` private mode still works): `iceland26.theme`, `iceland26.plan`, and per-plan booking ticks in `iceland26.bk.classic` / `iceland26.bk.highland`. `bkState` holds the live Sets; ticks are stored as a JSON array of **indices**, clamped per plan, so reordering a `bookings` array mis-restores old ticks. The plan key is restored *before* the top-level `let DAYS = PLANS[planKey].days` binding — restoring later leaves every builder on classic data. Saving happens **only** in the checkbox `change` handler, never in `updateProgress()`, which also runs during `switchPlan()` and would write one plan's ticks into the other's key.
- **Theme:** pre-paint `<head>` script applies the stored choice or `prefers-color-scheme`; the top-bar toggle saves only on explicit click. Design tokens live in `:root` with a full override set under `:root[data-theme="light"]`.
- **Daylight** (`DAYLIGHT` block at the end of the DATA section) — sunrise/sunset are **computed, never typed in**. NOAA solar-position equations, run **twice**: declination shifts ~23′/day near the equinox, so evaluating it once at midday skews sunrise and sunset ~2 min in *opposite* directions. Iceland is UTC+0 year-round, so UTC minutes are local minutes. Flat sea horizon (zenith 90.833° = refraction + solar radius), verified to the minute against published tables at Höfn (0 m); elevation dip is **deliberately not modelled** — it's worth 2–3 min while Iceland's real horizon is mountains worth far more, and the page says so in the section lede. A day's **sunrise is taken at the previous night's base** (where you wake and set off) and its **sunset at that day's own base**; on day 8 those are 5° of longitude apart, ~20 min, on a 430 km driving day. `sunEvent()` returns `null` for polar day/night and the strip is omitted rather than rendering dashes. Everything here is a **pure reader** — `dayLight(d, prev)` takes the predecessor as an argument precisely so nothing is memoized onto a shared day object.
- **Live Kp strip** in the aurora card fetches NOAA SWPC's `noaa-planetary-k-index-forecast.json` (CORS `*`, so it works from `file://` too). vedur.is sends no CORS headers so it is link-out only. On any failure the strip stays `hidden` — never give `.kpline` a `display` property, or `[hidden]` stops working and an empty strip renders on every failure.
- **`sw.js`** — navigations network-first with cached `index.html` fallback; shell assets cache-first; cross-origin (NOAA) passes through untouched. Cache name `iceland26-v4` — **bump the version when changing cached shell files.** It matters most for the cache-first assets (icons, manifest), which are otherwise never re-fetched; `index.html` also refreshes on any successful navigation, but a bump is what guarantees an offline-only client gets the new fallback copy. Registration is guarded to https/localhost, so `file://` use is unaffected.
- **`manifest.json`** + **`icons/`** — installable PWA identity (standalone, night-sky aurora icon).
- Sections: hero (countdown to ATL 18:45 Sep 18), plan tabs, map, sticky day rail, day cards, booking tracker, "Locked in" logistics (flights PNR CVYKHM, Blue Car #Z04F2O), aurora game plan, "The daily watch" resources, field notes, footer.
- **`docs/itinerary.md`** is generated — run `node tools/build-itinerary.mjs` after changing the itinerary, or `--check` to fail if it's stale. **`tools/build-itinerary.mjs`** evaluates the `DATA` section of `index.html` in a `node:vm` sandbox and renders both plans' day tables, base tables and booking checklists straight from `PLANS`; the prose sections are transcribed in the script's own template, so page copy and doc copy have to be edited together. It also pulls `dayLight`/`hhmm`/`hoursMins`/`shortBase` out of the sandbox rather than re-deriving daylight, and throws if `dayLight` goes missing — so the doc's sun times cannot drift from the page's. It keys off the `/* ==== DATA ==== */` and `/* ==== MAP ==== */` comment markers — renaming those breaks it loudly, by design. It's a docs tool, not a build step: `index.html` still ships as-is.

## History and constraints
Built in Claude.ai artifacts, where `localStorage`/`sessionStorage` are blocked — the tracker started in-memory out of necessity. Outside that sandbox the constraint is gone, and persistence, PWA/offline, light theme and live Kp all shipped (Aug 2026), followed by computed daylight. A per-day `.ics` export also shipped and was then removed on request (Aug 2026) — `git log` has it if it is ever wanted back.

## Conventions
- Stay single-file plus PWA shell and dependency-free unless there's a strong reason not to.
- Design tokens in `:root`; `--d1..--d10` day spectrum is an information system, not decoration; `--ember` = bookable, teal = soak. All theme-sensitive colors are tokens — never reintroduce literals. Deliberate exceptions kept literal: the soak teal, chip inks, the aurora border gradient, and the low-alpha green/amber tints.
- **Legend labels describe marker rules; statline numbers are trip facts.** Amber = "timed booking" (`tag:"book"` or `"booked"`), teal = "walk-in soak" (`tag:"soak"`). The hero's anchor-tour and soak-option counts are hand-maintained trip facts, not derived — the source comment above `PLANS.classic.stats` records the current tally and what each number counts, so update it and the number together. Some soaks are tagged `book` because they need reserving, and a paid soak (Earth Lagoon) counts as a soak rather than a tour so it isn't double-counted. Keep the two vocabularies disjoint — don't "reconcile" them into one count.
- **A day's `depart` is sometimes load-bearing, not taste.** Day 7 departs 08:20 because a 10:00 horse ride at Saltvík sits in front of a 12:30 whale sailing: 45 min to Húsavík, a stop to check in for the boat *early*, then 10 min out to the farm. It has been 08:10 and 07:55 as the whale booking moved (GG1 09:45 → GG2 09:30 → GG2 12:30) — when a tour is rebooked, this time moves with it. **The two bookings genuinely overlap:** the ride ends ~12:00 and standard whale check-in closes 11:50, so the plan relies on Gentle Giants' "arrive at the latest 40 minutes before" wording permitting an early check-in. That reasoning lives in day 7's `note` in both plans; don't "fix" the departure without reading it. Don't "tidy" a departure time without checking what constrains it — the reason is in a comment above the day.
- Preserve accessibility floor: visible `:focus-visible` styles, keyboard-operable map stops (`Enter`/`Space`), `prefers-reduced-motion` respected, print stylesheet working (all `<details>` auto-expand on `beforeprint`; controls, plan tabs, map links and the Kp strip hide in print). The plan switcher is deliberately **not** an ARIA tablist — it re-renders the whole page rather than one panel, so it's a `role="group"` of `aria-pressed` buttons, and `#plandesc` is `aria-live="polite"` so a switch is announced.
- **Anything derivable from `PLANS` is derived, not typed into the markup** — `#st-km`, `#st-stops`, `#st-soak`, `#st-flex` and `#st-booked` (nights with a confirmed `stay`) are all written by `switchPlan()`. Nights 4–10 are actively being booked, so a literal count would go stale. `10 nights` and the `$145–255` room-rate range are the only intentionally static numbers.
- All asset paths stay **relative** so subpath hosting works. The sole exception is the `og:url` / `og:image` social-preview pair, which scrapers require to be absolute — update those two if the deploy host moves.
- CSS: flat selectors, tokens over literals; watch specificity collisions. Two live examples: the day-dimming rule needs `#icemap .route path.dim` because a bare `#icemap .dim` loses to `#icemap .route path`; and print token overrides must target `:root[data-theme="light"]`/`[data-theme="dark"]` too, or the theme attribute out-specifies them.
- UI copy: sentence case, plain verbs, field-log tone. Mono face for anything data-like.
- `localStorage` keys are namespaced `iceland26.*`.
- Booked-stay facts, flight times, insurance list and booking references are ground truth — never alter without explicit instruction.
